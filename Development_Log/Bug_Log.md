# MERIDIAN Bug 与修复档案

本表只把可由提交、源码或现有设计/实施文档核验的内容写为“已证实”。早期五子棋与小游戏阶段没有逐项缺陷记录，不能倒填为既成事实。

| 阶段 | 现象与复现 | 原因 | 修复 | 经验 |
| --- | --- | --- | --- | --- |
| v3.0.0 | 成就详情关闭时视觉上重新放大；点击 X 后关闭延迟。 | 关闭插值错误反转；详情帧已累计过高。 | 移除反向计算，并在开始关闭时限制动画帧。 | 动画状态必须区分“打开进度”和“关闭进度”。 |
| v3.0.0 | 飞船皮肤列表的点击区域与绘制位置错开。 | 命中测试使用硬编码横坐标，绘制使用面板相对坐标。 | 两处共用同一坐标公式。 | 交互矩形应从布局数据产生，不能复制魔法数字。 |
| v3.0.0 | `TRIGGER HOUR FX` 无法触发。 | 动作被放进只处理 `air_*` 前缀的分支。 | 移至通用开发者动作入口。 | 用动作分发表时，要测试每个命名空间的可达性。 |
| v3.2.0 | 双方炮弹相撞的结果依赖更新顺序。 | 逐一更新时先处理的一方会获得不公平结果。 | 改为顺序无关的碰撞结算。 | 对称对战必须把“同一时间步”作为规则单位。 |
| v3.2.0 | 过载与重生分配会破坏对局平衡。 | 初版参数与重生安全条件经对局验证后不理想。 | 调整过载与重生分配规则，并加入安全点校验。 | 平衡不是常量微调；重生算法也是对局规则。 |
| v3.2.0 | 暂停状态仍会响应坦克道具输入。 | 暂停只冻结部分更新，输入路径未被拦截。 | 暂停时丢弃道具输入。 | 暂停需同时冻结时间、规则与一次性输入。 |
| v3.2.0 | 非法坦克快照可能在恢复时污染当前对局。 | 快照坐标与结构缺少充分验证。 | 版本化快照校验；恢复失败仅清除该局中断状态。 | 恢复失败必须局部降级，不能清除统计和其他游戏存档。 |
| v3.2.0 | Tank Duel 的中文统计、桌面标题可能对齐或溢出。 | 翻译后文本长度与英文布局假设不一致。 | 增加专用标题行、下调恢复按钮并修正本地化布局。 | 本地化是布局测试，不是字符串替换。 |
| v3.3.0-dev | Lore 条目点击无法打开。 | 档案入口的点击处理回归。 | 恢复点击处理并暴露 Tank Lore。 | 新数据接入后应覆盖“发现—打开—阅读”完整路径。 |
| v3.3.0-dev | 贪吃蛇从 JSON 恢复后可能发生碰撞判断异常。 | JSON 把坐标元组还原为列表，无法与元组集合正确比较。 | 恢复时统一转换为元组。 | 序列化边界要验证数据类型，不只验证数值。 |
| v3.3.0-dev | 已完成的游戏仍可能显示继续按钮。 | 完局状态未清除中断存档。 | 完成后废弃对应运行状态。 | “完成”和“中断”是互斥状态，应有显式清理。 |
| v3.3.0-dev | 成就墙页脚控制相互挤占。 | 同一区域承载多个控制元素。 | 分离页脚控制布局。 | 信息展示与可操作控件应分区。 |
| Unreleased | 普通 Lore 正文可读，但 Lore 完成度长期为 0，导致全局完成度最高只能达到 75%。 | 阅读状态写入 `read_entries`，条件完成事实却没有同步到 `unlocked_entries`。 | 增加统一条件求值与静默同步；启动时回填旧统计，运行中随统计和成就更新，普通正文继续保持可读。 | “能阅读”“已读过”“满足完成条件”是三种不同事实，必须分别建模并明确同步点。 |
| Unreleased | 鼠标可以打开尚未达到阈值的共鸣档案，而键盘会正确阻止。 | 两种输入走了不同的打开路径，鼠标分支没有调用门禁。 | 键盘和鼠标统一通过同一阅读检查，锁定标题显示为 `???`。 | 同一个动作的多种输入方式必须汇聚到同一领域函数。 |
| Unreleased | 清除全部进度后仍可能保留序章、已读 Lore、Lore 完成进度、共鸣条目，或继续内存中的 Tank 中断对局。 | 清理动作只重置了早期版本已有的数据分支，重新应用数据时也没有先清空内存快照。 | 清除动作覆盖序章和整个 Lore 进度，并在重新扫描存档前清空待恢复对局；恢复默认设置仍只改设置。 | “清除进度”和“恢复设置”应拥有互不混淆的重置边界，磁盘与内存缓存也必须同步清理。 |
| Unreleased | 旧 v5 存档的 Tank 完成度读取缺少对局、胜场或骤死胜场字段。 | Tank 运行时动态写入的统计没有全部进入默认结构和兼容回填。 | 补齐缺省键，并从旧字段安全回填。 | 运行时会产生的持久字段必须同时出现在默认值、迁移与测试里。 |

## 未作为事实写入的早期问题

五子棋磁吸、连线动画以及早期五款小游戏的体验调整是真实开发节点，但仓库没有保存当时的异常堆栈、复现步骤或修复提交。因此完整开发史中只会把相应的失败和测试写为【推测】或概括性体验判断，不把它们列为已证实 Bug。
