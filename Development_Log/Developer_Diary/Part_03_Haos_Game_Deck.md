# 第三部分：从游戏桌面到 HAO'S GAME DECK

---

## 记录 21｜选择界面能用，但始终像一张临时菜单

小游戏合集的进入和返回已经跑通，但我连续使用几次以后，越来越觉得那个选择界面只是一个过渡方案。

它只有标题和游戏入口。玩家可以从这里打开五子棋，却看不出这些游戏为什么会被放在一起。增加入口也只是继续往页面上加按钮，游戏数量一多，最后很可能变成一张越来越长的列表。

功能上，它已经完成了“方便选择”；体验上，它还没有形成自己的身份。

我开始思考，能不能把每个小游戏当成一个软件，不再使用普通菜单按钮，而是把它们放到一个桌面上。这样玩家看到的就不是“选择第几个游戏”，而是“打开哪个软件”。

这个变化暂时不涉及新的游戏规则，只是重新设计所有游戏共同使用的入口。

---

## 记录 22｜第一次做桌面，先把列表改成图标网格

桌面的第一版仍然保持简单：一张独立背景、一个顶部区域，以及用于放置游戏的软件图标。

我没有继续使用纵向按钮列表，而是把可用区域分成三列两行。每页最多显示六个软件，每个图标使用相同大小的方形卡片。这样以后入口增加时，位置仍然由网格计算，不需要为每个游戏手动调整坐标。

布局大致变成：

```text
┌─────────────────────────────────────┐
│              顶部区域               │
├─────────────────────────────────────┤
│                                     │
│      [ 01 ]    [ 02 ]    [ 03 ]    │
│                                     │
│      [ 04 ]    [ 05 ]    [ 06 ]    │
│                                     │
└─────────────────────────────────────┘
```

图标尺寸先定为 124 像素。横向和纵向间隔不写成固定位置，而是根据桌面可用宽高重新计算：先减去全部图标占用的空间，再把剩余空间平均分配到网格边缘和图标之间。

桌面背景与五子棋的木质棋盘分开，改用深蓝到蓝紫色的纵向渐变，并放入少量会轻微明暗变化的像素星点。我希望玩家退出五子棋时，能立刻从颜色上感觉自己已经回到了另一个层级，而不是仍停留在棋盘界面里。

---

## 记录 23｜软件图标不能只是换一种形状的文字按钮

第一版图标如果只在方框中写 `GOMOKU`，实际效果和之前的菜单按钮区别不大，只是从长方形变成了正方形。

所以我给五子棋画了一个独立的像素图标：内部是一块缩小的木色棋盘，画出几条网格线，再放一枚黑棋和一枚白棋。即使暂时不看下面的文字，也能大致认出它代表什么。

图标本身也增加了三种状态：

```text
普通：保持标准尺寸
悬停：卡片轻微放大，并在后方出现阴影
按下：卡片向下移动几像素
```

最初只在鼠标按下时立即打开游戏，测试时发现操作缺少取消机会。鼠标按住以后即使移出了图标，游戏仍然会进入。

我把点击拆成按下和松开两个阶段：按下时只记录当前图标并显示下压效果；松开时，只有鼠标仍在同一个图标内才执行打开。如果按住后移出图标，这次点击就取消。

这个处理让软件图标更像一个可以按下的实体控件，也避免了一次不完整的点击直接改变页面。

---

## 记录 24｜桌面做好以后，问题反而更清楚了

把五子棋放进桌面以后，合集看起来确实比原来的选择页更有结构。图标有了固定位置，背景也与游戏内部区分开，进入和返回仍然使用之前整理好的状态切换。

但实际运行后，我还是觉得少了什么。

这张桌面像一个普通程序里的软件启动器：它可以放图标，却没有边界，也没有说明自己属于什么。玩家看到的是一整块占满窗口的界面，顶部加一行信息，下面放几张卡片。即使使用像素风，它仍然更像“做成桌面样式的菜单”，而不是一个完整的东西。

这次问题已经不能靠继续美化背景解决。再增加渐变、边框或装饰，只会让菜单更精致，不会改变它的身份。

我开始觉得，与其模仿电脑桌面，不如把整个项目做成一台类似掌机的设备。桌面不再直接铺满程序窗口，而是显示在掌机自己的屏幕里；所有小游戏也不再只是放在同一张菜单上，而是安装在同一台设备中。

---

## 记录 25｜正式给这台掌机起名：HAO'S GAME DECK

决定把合集做成掌机以后，需要一个能出现在设备外壳和系统界面上的名字。

我把它正式命名为：

```text
HAO'S GAME DECK
```

`GAME DECK` 表达它是一台承载多款游戏的设备，而不是某一款游戏的标题。这个名字确定以后，项目的设计单位也发生了变化。

以前我主要考虑：

```text
五子棋页面应该怎样显示？
选择按钮应该放在哪里？
```

现在还要考虑：

```text
设备的屏幕在哪里？
桌面信息怎样排列？
软件图标怎样表现可用与不可用？
玩家进入和退出游戏时，回到的是哪个层级？
```

命名不是最后补在标题栏上的一行文字。确定它是一台 `GAME DECK` 后，外壳、屏幕和桌面都需要围绕“这是一台设备”重新安排。

## 记录 26｜先把桌面装进一个真正有边界的屏幕里

原来的桌面直接使用整个 `1280×720` 窗口。改成掌机以后，我先划出两层区域：最外层是设备外壳，里面才是桌面屏幕。

```python
WINDOW_W = 1280
WINDOW_H = 720

HANDHELD_RECT = pygame.Rect(
    36, 22,
    WINDOW_W - 72,
    WINDOW_H - 44,
)

DESKTOP_SCREEN_RECT = pygame.Rect(
    120, 78,
    WINDOW_W - 240,
    WINDOW_H - 156,
)
```

外壳离窗口四边保留较窄距离，屏幕再向内缩进。这样桌面周围会自然留下边框空间，而不是另外在背景上画一个没有厚度的矩形。

外壳主体使用深棕色，外侧加深色粗描边和暗金色内描边；屏幕边缘再增加一层黑色边框和金色细线。四角各放一个小型金属角块，并用亮色像素表示反光。

我没有把外壳做得非常复杂，因为这时最重要的是先建立层次：

```text
程序窗口
   ↓
掌机外壳
   ↓
设备屏幕
   ↓
桌面与软件图标
```

只要这四层在视觉上能够被分开，桌面就不再像贴满整个窗口的普通菜单。

---

## 记录 27｜有了外壳以后，所有桌面内容都必须被屏幕裁住

给桌面套上外壳后出现了一个新的绘制问题。

背景渐变、图标和分页动画仍然按照整个窗口绘制。静止时不明显，但图标横向移动时会越过屏幕边缘，直接画到掌机外壳上，看起来像软件卡片从屏幕里穿了出来。

解决方法不是给每个图标分别判断是否越界，而是在绘制桌面内容前设置统一裁剪区域：

```python
old_clip = screen.get_clip()
screen.set_clip(DESKTOP_SCREEN_RECT)

draw_wallpaper()
draw_desktop_icons()

screen.set_clip(old_clip)
```

桌面背景、软件图标和分页移动只能出现在 `DESKTOP_SCREEN_RECT` 内；掌机外壳则在裁剪区域之外单独绘制。

第一次修改时，我在桌面绘制结束后忘记恢复原来的裁剪范围，结果后面的外壳装饰也有一部分不再显示。补回 `old_clip` 以后，屏幕内部和外部才真正成为互不干扰的两层。

这次问题让我意识到：既然已经把界面定义成一台设备的屏幕，屏幕边缘就不能只是一条装饰线，它还应该是实际的绘制边界。

---

## 记录 28｜时钟和电量不是装饰，它们负责证明这是设备桌面

外壳完成以后，桌面仍然需要一些不属于任何单独游戏的信息。

我在屏幕顶部增加状态栏：左侧显示当前时间，中间显示 `HAO'S GAME DECK`，右侧显示电量。

```text
┌─────────────────────────────────────┐
│  14:32       HAO'S GAME DECK  BAT 96% │
└─────────────────────────────────────┘
```

时间直接读取系统当前的小时和分钟。电量则使用一个很简单的模拟值：程序启动时为 100%，随后根据运行时间缓慢下降，暂时按 40 分钟降到 0% 计算。

```python
elapsed = pygame.time.get_ticks() - app_start_ticks
ratio = max(0.0, 1.0 - elapsed / BATTERY_DRAIN_MS)
battery = round(ratio * 100)
```

这时的电量还不会影响游戏运行，也不负责触发其他流程。它首先是一种桌面信息：玩家在任何游戏之外都能看到同一时间和同一电量，说明这些游戏处于同一台设备中。

状态栏使用深色面板和底部金色细线，与桌面内容分开。左、中、右三块信息分别锚定到状态栏两端和中心，避免名称长度变化时把时钟或电量挤走。

## 记录 29｜只有一个可用图标时，掌机看起来像已经停止开发

掌机外壳和桌面完成后，新的问题是内容太空。

屏幕上只有五子棋一个可用软件。其余位置如果完全留白，玩家很难看出这里准备承载一个游戏合集，也无法判断空白是设计选择，还是界面还没有画完。

我不想为了填满桌面而放入尚未开发的假游戏，于是决定预留 12 个软件栏，并统一写成：

```text
COMING SOON
```

这些栏位使用与正式游戏相同的外部尺寸，保证桌面结构不会因为内容未完成而塌掉；内部则改成灰暗面板和像素锁图案，文字也使用低亮度颜色。

它们只表达“这里以后可以放入内容”，不能假装已经可用。因此每个预留栏都明确设置为禁用状态：鼠标悬停时不使用正式软件的高亮，点击时也不会进入任何页面。

`COMING SOON` 解决了两个不同问题：

- 视觉上，它让掌机桌面从单个图标变成有明确容量的软件区域；
- 开发上，它把尚未完成和已经可用的内容区分开，不需要用一个没有功能的按钮冒充游戏。

预留栏不是功能承诺表，我也没有在上面提前写具体游戏名称。当前只确定这台掌机会继续增加内容，至于每个位置最终放什么，等真正开始开发时再决定。

## 记录 30｜12 个预留栏放不进一页，所以桌面开始支持分页

每页采用三列两行，只能放六个软件。加入 12 个 `COMING SOON` 预留栏以后，继续把图标缩小塞进同一页会让图案和文字都难以辨认。

我保留图标大小，给桌面增加左右分页按钮和页码圆点。点击箭头时，当前页横向移出，目标页从另一侧进入。

分页动画先设为 36 帧，并使用三次缓入缓出：

```python
def ease_in_out_cubic(t):
    if t < 0.5:
        return 4 * t * t * t
    return 1 - (-2 * t + 2) ** 3 / 2
```

如果所有图标完全同步移动，整页看起来像一张平面图片。我又给进入页的图标增加很小的时间错位，让它们按照排列顺序略微延迟，并在移动中向上抬起几像素。

分页过程中暂时停止处理软件图标点击。否则图标已经画在移动位置，命中区域却可能仍按静止页面计算，玩家会点中正在离开的软件，或者在动画结束前再次启动另一段分页。

动画结束后再一次性确认当前页、清除按压状态并恢复输入。这样分页不仅看起来连续，内部状态也只在确定的时刻完成切换。

## 记录 31｜反复进入、返回和翻页后，掌机雏形才算稳定

这一轮测试不再只检查五子棋本身，而是围绕设备桌面反复操作：

```text
打开程序并看到掌机桌面
   ↓
悬停、按下并进入五子棋
   ↓
从五子棋返回桌面
   ↓
连续切换桌面分页
   ↓
点击 COMING SOON 预留栏
   ↓
再次进入五子棋
```

我重点确认了这些结果：

- 五子棋图标只有在同一图标内按下并松开才会启动；
- 返回后仍然回到设备屏幕里的桌面，不会跳回旧选择页；
- 页面移动期间不能误触图标，也不能重复开始另一段滑动；
- 桌面内容不会越过屏幕边框画到外壳上；
- 12 个 `COMING SOON` 栏位始终不可点击；
- 多次进出五子棋后，桌面时钟和模拟电量仍按同一设备状态继续显示。

到这里，项目第一次有了一个明确的外部形态。

它不再只是五子棋前面加了一层选择菜单，也不再只是一张模仿电脑的桌面。`HAO'S GAME DECK` 现在是一台有外壳、有屏幕、有状态栏、有软件栏和分页结构的虚拟掌机。

这台掌机目前仍然很空：真正能打开的只有五子棋，其余位置只是锁住的预留栏。但这种“空”与之前的空白页面不同。现在我已经知道新内容应该放到哪里、怎样从桌面进入，以及退出后应该回到什么地方。接下来可以开始逐个完成新的小游戏，再把它们真正装进这些位置。
