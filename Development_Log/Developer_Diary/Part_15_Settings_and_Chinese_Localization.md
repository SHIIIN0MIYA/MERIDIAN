# 第十五部分：选项越来越分散，我开始做统一设置中心和简体中文版本

---

## 记录 199｜第七款游戏加入以后，玩家要记住的选项已经分散在很多页面

空袭行动完成后，我重新检查整台掌机的可调整内容。

音乐和音效有自己的内部音量，五子棋可以更换棋盘大小，贪吃蛇有速度与外观，打砖块有控制方式与难度，扫雷有棋盘规模。部分选项放在游戏自己的设置页，部分还只存在于代码默认值里。

这带来两个问题。

第一，玩家想关闭震动或调低音乐时，不应该先进入某一款游戏寻找；这些属于整台掌机。第二，修改过的值如果程序关闭后全部恢复，设置就只是临时调试按钮，不是产品功能。

我决定在桌面增加一个独立的设置入口，把系统级选项和各游戏常用选项集中在同一页，同时建立正式的本地保存结构。

这一阶段还要解决另一个一直存在的使用门槛：所有页面主要使用英文。与其复制出一份单独维护的中文程序，我决定让同一套代码能够在英文和简体中文之间切换。

所有按钮继续遵守按下与松开位置一致才执行的规则。设置中包含全屏、重置等影响较大的操作，不能在鼠标按下瞬间直接触发。

## 记录 201｜音乐和音效分开调整，静音只覆盖输出，不破坏原来的音量值

背景音乐与玩法音效的使用场景不同。有人可能希望保留碰撞反馈、只把循环音乐调低，也可能临时让整台掌机静音。

我保留三层控制关系：

```text
music_volume   背景音乐音量
sfx_volume     短音效音量
muted          最终是否输出
```

设置页的 `-` 与 `+` 每次调整 0.1，并在 0 到 1 之间限制。页面显示三位百分比，例如 `055%`。

静音没有把两个音量直接写成零，而是在最终计算时返回零输出。取消静音后，音乐和音效恢复静音前的比例。

第一次用“静音等于把音量设为零”的方案测试时，取消静音无法知道玩家原来使用 30%、55% 还是 100%。把开关与数值分开以后，临时静音才不会破坏已经调好的设置。

## 记录 202｜全屏不能直接把所有坐标乘大，否则画面和鼠标命中区会分离

项目里的界面全部按 1280×720 逻辑坐标设计。直接把窗口改成显示器分辨率后，如果仍然按原坐标绘制，画面只占左上角；如果只缩放画面，鼠标事件又仍然使用物理坐标，点击位置会错开。

我保留一张固定逻辑画布 `screen`，再把它缩放到真实显示表面：

```python
scale = min(display_width / 1280, display_height / 720)

offset_x = (display_width - 1280 * scale) / 2
offset_y = (display_height - 720 * scale) / 2
```

多余区域使用黑色留边，保持原始宽高比。绘制结束时只缩放最终帧，不修改各游戏内部坐标。

鼠标事件进入页面以前做反向映射：

```python
logical_x = (physical_x - offset_x) / scale
logical_y = (physical_y - offset_y) / scale
```

我用两倍缩放并增加偏移构造测试，物理坐标 `(300, 250)` 应该映射回逻辑坐标 `(100, 100)`。只有绘制和输入使用同一变换，全屏按钮才不会出现“看见在这里，实际要点旁边”的问题。

## 记录 203｜动画等级与屏幕震动需要成为系统选项，因为它们跨越多款游戏

随着反馈越来越多，棋子回弹、粒子、转场、爆炸和屏幕震动可能让部分玩家觉得过强，也会增加性能压力。

我把动画等级设为循环三档：

```text
FULL       完整动画
REDUCED    缩短转场、减少粒子
OFF        使用最短切换并关闭非必要效果
```

它不是一个只改变文字的标记。转场启动时读取等级，`REDUCED` 把帧数压缩，`OFF` 使用最低帧数；会生成大量粒子的效果也根据等级减少数量或直接跳过。

屏幕震动单独作为开关。关闭后不只是不再创建新震动，还会在更新循环中把已经进行的震动计时和偏移清零。否则玩家在一次爆炸中途关闭选项，画面仍会继续抖到旧计时结束。

动画和震动分开，是因为玩家可能接受粒子与缓动，却不适应整张画面位移。

## 记录 204｜统一设置页只放常用入口，各游戏原有的专属设置仍然可以保留

设置中心不是要求所有游戏拥有完全相同的选项，而是提供一处可预期的入口。

五子棋棋盘大小、贪吃蛇速度、打砖块难度和扫雷规模会明显改变一局游戏，所以放入右侧列。外观或控制细节仍然可以保留在各游戏自己的页面，避免系统设置无限增长。

我为每个循环选项定义固定顺序：

```text
五子棋棋盘      15 → 19 → 13 → 15
贪吃蛇速度      SLOW → NORMAL → FAST
贪吃蛇外观      GREEN → LIME → RED
打砖块控制      KEYBOARD ↔ MOUSE
打砖块难度      EASY → NORMAL → HARD
扫雷棋盘        9×9/10 → 9×9/15 → 9×9/20
                → 16×16/40 → 16×16/50 → 16×16/60
```

按钮显示的不是内部动作名 `cycle_snake_speed`，而是当前真实值。每次点击后立即刷新，玩家不需要退出再进入才能确认修改结果。

## 记录 205｜五子棋进行到一半时修改棋盘大小，不能直接销毁当前棋局

五子棋棋盘大小会影响 `Board` 对象、格子尺寸、星位和棋子纹理。如果在设置中心点击后立即创建新棋盘，玩家进行中的棋局会在没有确认的情况下消失。

我先更新偏好值，但只在当前棋盘为空或已经结束时重建：

```python
board_size = next_board_size

if not board.has_moves() or board.winner:
    board = Board(board_size)
    rebuild_stone_assets()
```

进行中的棋局继续使用原来的棋盘对象。下一次开始新局时，再按新的大小创建。

这也让我意识到，设置值和正在运行的对局状态不是同一件事。设置代表“以后怎样开始”，不能因为偏好改变就无条件改写当前游戏。

## 记录 206｜贪吃蛇速度和外观可以立即应用，但要通过同一个偏好函数

贪吃蛇速度最终对应移动间隔：

```python
slow   = 11 帧
normal = 8 帧
fast   = 6 帧
```

外观则同时决定身体和头部颜色。设置中心如果分别修改这些运行字段，游戏自己的设置页又维护另一套映射，两边迟早会出现不一致。

我让两个入口都只修改 `snake_speed_mode` 或 `snake_skin`，随后调用同一个 `_apply_snake_preferences()`。

第一次切换外观时只改了身体颜色，蛇头仍然保留旧色，说明直接散改字段很容易遗漏。集中映射以后，每个外观都成对提供身体和头部颜色，速度也只从一张表转换为帧间隔。

修改后返回贪吃蛇菜单即可看到新的预览，开始下一局时使用新速度。

## 记录 207｜打砖块的控制方式和难度不只是显示选项，必须重新应用到运动参数

打砖块支持键盘与鼠标两种挡板控制。设置中心切换时只保存 `keyboard` 或 `mouse`，对局读取同一个字段决定挡板位置来源。

难度则影响球速、挡板和生命压力。它不能只在页面上从 `NORMAL` 变成 `HARD`，必须调用统一的难度应用函数重新计算相关参数。

```python
breakout_difficulty = next_value
apply_breakout_difficulty()
```

外观偏好也集中保存球、砖块和挡板的选择，再由一处映射成实际颜色。这样设置从存档恢复时，与玩家在游戏内修改时走相同应用路径。

我在键盘和鼠标模式间来回切换，并重新进入对局，确认旧模式的速度或鼠标位置不会继续控制新的挡板。

## 记录 208｜扫雷把棋盘尺寸和地雷数作为一组切换，避免出现未验证组合

扫雷的格子数与地雷数必须成对考虑。允许玩家分别无限增加，会轻易得到地雷多于可用格、首击安全区无法布雷或密度完全失控的组合。

我没有提供两个自由数字输入框，而是准备六组已经验证过的模式：

```python
(9, 10)
(9, 15)
(9, 20)
(16, 40)
(16, 50)
(16, 60)
```

设置页每次只循环到下一组，显示 `尺寸 × 尺寸 / 地雷数`。

偏好改变不会在进行中的棋盘上重新布雷。它决定下一次新建扫雷局使用的规模，避免玩家在已经翻开格子后通过设置修改剩余地雷总数。

固定组合减少了自由度，但保证每个入口都能生成合法棋盘，也让最佳时间可以按明确模式分别保存。

## 记录 209｜“恢复设置”和“清除进度”必须是两个不同操作，并且都需要二次确认

第一次设计底部按钮时，最危险的做法是放一个含糊的 `RESET`。玩家无法判断它会重置音量，还是连最佳分数和关卡进度一起删除。

我拆成：

```text
DEFAULT SETTINGS
  恢复音量、显示、动画和游戏偏好
  保留成绩与进度

ERASE PROGRESS
  清空成绩、统计与关卡进度
  保留当前设置
```

两者点击后都先打开带暗色遮罩的确认面板。只有在确认按钮上完成按下和松开，才执行真正修改；`ESC` 或取消按钮关闭面板。

我分别构造“音乐音量已改、贪吃蛇最高分已存在”的数据。恢复设置后音量应回到默认、最高分仍在；清除进度后最高分归零、音量仍保持修改值。

操作边界必须通过数据测试确认，不能只依靠按钮文案。

数据带有 `schema_version`。以后增加字段时，旧文件通过默认结构进行深度合并，缺少的新字段使用默认值，已有字段继续保留；不能因为新增一个语言或选项就让旧存档无法读取。

## 记录 211｜直接覆盖 `save.json` 有断电风险，我改为临时文件、备份和原子替换

第一次想到保存时，最简单的方式是直接打开原文件写入。如果程序刚好在写到一半时退出，下一次启动读到的会是一段不完整 JSON，所有设置和进度都可能丢失。

我把保存流程改成：

```text
1. 把完整数据写入 save.json.tmp
2. flush 并调用 fsync，确保内容真正落盘
3. 如果旧 save.json 存在，复制为 save.json.bak
4. 用临时文件原子替换正式文件
```

加载时如果正式文件解析失败，先把坏文件改名为带时间标记的 `save.corrupt-...json`，然后尝试备份；备份也不可用才回到默认数据。

我先保存一份旧分数，再保存一份新分数，确认备份仍然保存旧值；随后故意写入错误 JSON，检查程序能够隔离坏文件并从备份恢复。

设置中心让本地数据第一次变得重要，因此保存失败不能继续被当作一次普通异常。

## 记录 212｜每一帧都写存档会浪费磁盘，只在数据变化时按间隔保存

空袭行动包含分数、关卡、武器与任务进度，其他游戏也在不断修改统计。如果每次变化都立即写文件，高频操作会造成大量磁盘写入。

我保存上一次持久化数据的序列化快照，每隔约 2000 毫秒检查一次：

```python
snapshot = json.dumps(capture_data(), sort_keys=True)

if snapshot != last_persisted_snapshot:
    save_now()
else:
    update_check_time_only()
```

关键操作仍然可以主动保存，例如切换设置、完成关卡和正常退出；普通运行数据则由间隔检查合并写入。

固定排序保证相同数据每次生成相同字符串，不会因为字典顺序变化被误判为修改。

我让程序停留在没有任何变化的页面超过多个检查周期，确认不会重复写文件；修改一个音量后，下一个保存点应产生新快照。

## 记录 213｜中文切换不能只放在设置中心，否则玩家要先读英文才能找到语言选项

如果简体中文入口只存在于桌面设置，第一次启动的玩家必须先看懂开机页面、密码提示和桌面图标，才能进入设置修改语言。

我把语言选择提前到 `SYSTEM READY` 页面。系统加载完成后，玩家可以用左右键切换，也可以直接点击：

```text
[ ENGLISH ]    [ 简体中文 ]
```

选择只改变当前语言，不会跳过进入按钮；玩家确认以后再进入密码页。

设置中心仍然保留同一个语言开关，方便之后随时修改。两个入口都调用统一的 `set_language()`，不各自维护页面副本。

这使汉化不是另一个可执行文件，而是同一台掌机的运行时语言。修复玩法或界面时只维护一套代码，两种语言读取相同状态和数据。

## 记录 214｜只用英文字串作为字典键，第一批静态按钮能翻译，动态内容却全部漏掉

我先建立英文到简体中文的映射：

```python
ZH = {
    "SETTINGS": "设置中心",
    "BACK": "返回",
    "MUSIC": "音乐",
    "SFX": "音效",
    "GAME OVER": "游戏结束",
}
```

静态标题和按钮很快能够显示中文，但测试对局时出现大量半翻译内容：`SCORE 1200`、`LEVEL 3`、`TIME 00:42` 每次数字不同，无法为所有组合准备字典项。

我给动态字符串增加正则规则：

```python
r"^SCORE (\d+)$"           → r"得分 \1"
r"^LINES (\d+) LEVEL (\d+)$" → r"消行 \1　等级 \2"
r"^TIME (.+)$"             → r"时间 \1"
```

翻译函数先查精确字典，找不到再尝试动态规则，仍然没有匹配才返回原文。

这样未知文本不会让页面报错，动态数字也不需要在代码里分别写中英文分支。

## 记录 215｜翻译必须进入公共文字渲染入口，否则每个页面都会漏掉几行

如果要求每次绘制文字前都手动调用 `translate()`，很容易出现标题翻译了、按钮说明没翻译，或者新加文字忘记处理。

项目大部分像素文字都经过 `render_pixel_text()`，我把翻译放在这个公共入口：

```python
def render_pixel_text(font, text, color, scale=2):
    text = translate(str(text))
    render_font = chinese_font if contains_chinese(text) else font
    small = render_font.render(text, antialias, color)
    return pixel_scale(small, scale)
```

这样原来的游戏代码仍然可以传英文源文本，当前语言为中文时自动转换；英文模式完全返回原字符串。

第一次全局测试时，仍有少量页面直接调用 `font.render()`，绕过了公共入口。这些文字在中文模式下保持英文。我逐页检查并把需要本地化的显示改回公共渲染函数。

问题不在翻译表够不够大，而在所有可见文字是否真正经过同一条管线。

## 记录 216｜默认英文字体没有中文字形，我把简体中文像素字体作为正式资源加入项目

翻译函数返回中文以后，原字体只会显示方框或空白。汉化不能只改字符串，还需要覆盖所用汉字的字体资源。

我加入简体中文像素字体，并保留对应许可文件。渲染时先检查字符串是否包含中文字符；只有需要时才切换字体，英文继续使用原来的界面字体。

字体路径还要同时兼容源码运行和打包：

```python
root = Path(getattr(sys, "_MEIPASS", project_root))
font_path = root / "assets" / "fonts" / "fusion-pixel-12px-proportional-zh_hans.ttf"
```

不同字号的字体对象按尺寸缓存，避免每绘制一行中文都重新读取文件。

中文使用关闭抗锯齿的小尺寸渲染，再按整数倍放大，使边缘与现有像素界面保持一致，不会变成一层过于平滑的普通系统字体。

## 记录 217｜翻译正确不代表排版正确，中文与英文的宽度变化会让按钮溢出

同一句内容在两种语言中的宽度并不固定。英文可能很长，中文可能更短；某些四字中文标题又会因为字体字面框而比预想更宽。

第一轮切换后，我发现部分按钮文字贴近边框，空袭行动的较长状态行也会超过信息面板。只翻译内容而不重新检查布局，页面仍然不可用。

我给通用按钮加入宽度保护：先按正常像素倍率渲染，如果超过按钮可用宽度，就降低到更小倍率。需要保持标题视觉重量的地方则使用“在最大宽度内寻找合适倍率”的文字拟合函数，而不是直接截断。

动态说明使用按实际渲染宽度换行，不能再依靠固定字符数。因为一个汉字、一个英文大写字母和一个空格的像素宽度并不相同。

我在英文和中文之间来回切换，逐页检查标题、按钮、状态栏、操作提示和结束页，确认不存在文字越界后才把汉化视为完成。

## 记录 218｜语言切换必须立即生效，并且重启后继续使用上次选择

切换语言后，我没有重建所有页面对象，因为大部分文本本来就是每帧按当前状态渲染。`set_language()` 只更新全局语言，下一次绘制就会读取新的翻译。

语言值同时写入设置：

```python
settings["language"] = language
```

程序启动并加载存档后，先应用语言，再绘制开机和系统页面。这样上一次选择简体中文，下一次启动不会先显示一段英文开机流程、到桌面才突然切换。

我测试了三条路径：在系统就绪页选择中文、在设置中心切回英文、关闭程序后重新启动。每次页面都应立即改变，重启后保持最后选择。

语言是系统设置，不应该依赖玩家进入过哪一款游戏。

---

## 记录 219｜设置恢复后必须重新“应用”，只修改 JSON 不会自动改变正在运行的对象

确认恢复默认设置以后，保存数据中的字段已经变回默认值，但当前音频管理器、显示模式、棋盘和游戏偏好仍然保存在内存中。

如果只写存档、不重新应用，页面会显示默认值，实际音乐音量和蛇速却继续使用旧值，直到下次重启才一致。

我把加载和恢复都汇入 `_apply_loaded_data()`：

```text
读取 settings
  → 设置当前语言
  → 应用音乐、音效与静音
  → 应用窗口模式、动画和震动
  → 重建允许重建的棋盘资源
  → 应用贪吃蛇与打砖块偏好
  → 恢复扫雷模式
```

恢复默认和清除进度完成后都重新调用这一入口，再保存一次最终状态。

这避免了“存档中的设置”和“当前正在使用的设置”成为两套不同真相。

## 记录 220｜最终测试必须覆盖重启、全屏坐标和两种语言，而不是只看设置页按钮会变

完整测试路径包括：

```text
打开设置中心
  → 分别调整音乐与音效
  → 静音再取消，确认原音量恢复
  → 切换全屏，检查画面比例和鼠标命中
  → 关闭震动并在爆炸中确认偏移立即清零
  → 循环修改六组游戏选项
  → 切换简体中文，逐页检查文字与布局
  → 退出并重新启动，确认设置仍然存在
  → 恢复默认，确认成绩和进度保留
  → 清除进度，确认设置保留
  → 破坏正式存档，确认能够从备份恢复
```

我还在没有中文字符的英文页面和包含数字的动态中文页面之间反复切换，确认字体选择、正则翻译和缓存不会互相污染。

设置中心完成后，掌机第一次不再假定所有玩家都使用同一种音量、动画强度、控制偏好和语言。汉化也不是在原界面上额外覆盖几行中文，而是从字体、动态文本、布局、全屏输入到持久化共同组成的一套运行时语言系统。
