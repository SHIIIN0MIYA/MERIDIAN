# 第十八部分：我不只想保存最高分，还想让玩家看见自己在整台掌机里走了多远

---

## 记录 257｜成就墙回答“完成了什么”，却回答不了“我到底玩了多少”

成就墙做完以后，48 个目标终于有了固定位置。但我打开它时仍然只能看到被预先定义过的里程碑。

如果一名玩家在扫雷上花了很长时间，却还没达到十胜；或者反复挑战俄罗斯方块，把最高等级一点点推高，这些过程不会完整反映在几枚徽章上。

我想做一个真正以玩家为中心的页面：不是继续增加奖励，而是把已经产生的成就、总时间和各游戏记录整理成一份可回看的玩家档案。

它的目的也很明确——让玩家看见自己还没有完成的部分，从而愿意把某款只玩过一次的游戏重新打开并真正通关。

---

## 记录 258｜我先限制玩家档案只做两件事：成就进度和统计总览

最开始我列过很多可能加入的内容：最近游玩、个人称号、头像、收藏品、推荐挑战。继续扩展下去，它很快会变成第二个桌面系统。

我先把范围缩回已经有可靠数据的两部分：

```text
ACHIEVEMENTS
  查看 48 项目标、当前进度和完成时间

STATISTICS
  查看全局使用情况和每款游戏的长期数据
```

档案不改变玩法，也不新增需要维护的奖励资源。它只整理现有存档，让之前埋在 JSON 里的数字对玩家可见。

---

## 记录 259｜玩家档案不能自己统计，所有数字继续来自统一记录入口

我没有在打开档案时重新扫描各游戏对象，因为很多游戏此时根本没有处于运行状态，内存中的分数也不一定代表已完成结果。

档案直接读取统一存档：

```python
save_data["statistics"]
save_data["achievements"]
save_data["records"]
```

各游戏仍然只在规则真正发生时调用统计入口，档案只负责格式化和展示。这样关闭程序再打开，页面内容仍然一致；重置设置也不会误删记录，只有明确清除进度才会重建这些数据。

---

## 记录 260｜全局统计先回答四个最基本的问题

我给档案最上层保留了四项全局数据：

```text
LAUNCHES         启动次数
PLAY TIME        总游玩时间
GAMES STARTED    开始过多少局
GAMES COMPLETE   真正完成多少局
```

“开始”与“完成”必须分开。玩家进入菜单不算开始一局，按下新游戏并创建有效状态才记录；中途退出会增加开始数，但不会伪装成完成。

这个差值本身就是有意义的反馈：如果开始过很多局、完成很少，说明某些游戏的中途退出较多，也能提醒我检查难度或恢复体验。

---

## 记录 261｜每款游戏显示的统计不同，不能为了统一而全部只放分数

七款游戏没有共同的“最好表现”定义。我为每款游戏选择能解释其玩法的字段：

```text
五子棋       完成局数 / 黑胜 / 白胜 / 撤销
贪吃蛇       开始局数 / 最高分 / 食物总数 / 死亡次数
打砖块       最高分 / 最高关卡 / 击碎砖块 / 通关数
2048         最高分 / 最大方块 / 有效移动 / 合并次数
扫雷         胜利 / 失败 / 翻开格 / 插旗数 / 各模式最快时间
俄罗斯方块   最高分 / 最高等级 / 消行总数 / 四消次数
空袭行动     最高分 / 最高任务 / 击毁数 / S 评级数
```

如果强行每款都只显示 `BEST SCORE`，扫雷的速度、五子棋的双方胜场和空袭行动的评级都会被抹掉。统一页面不应该把不同玩法压成同一种数据。

---

## 记录 262｜统计字段的名称必须和写入语义完全一致

制作页面时，我再次遇到累计值与最高值容易混淆的问题。

例如俄罗斯方块的 `LINES` 在档案里表示长期消行总数，而单局最高消行应使用另一个字段；2048 的 `MOVES` 只统计真正改变棋盘的操作，按了方向但棋盘不动不能增加；扫雷的最快时间只在对应尺寸与雷数获胜时更新。

我逐项沿着页面标签回查写入位置，确认：

```text
add 字段 → 页面展示累计结果
max 字段 → 页面展示历史最佳
模式字典 → 页面必须带模式名称
```

展示层一旦把含义写错，即使底层数字计算正确，玩家得到的结论仍然是错的。

---

## 记录 263｜游玩时间只在游戏真正运行时增加，菜单停留不能算成绩

总时间和分游戏时间最初看起来只需要每帧累加 `dt`，但状态范围如果过宽，玩家在桌面发呆或停在游戏菜单也会让统计增长。

我建立当前游戏状态到统计分类的映射，只在实际对局状态计时。暂停状态仍属于一局中的停留，但桌面、设置、档案和结束页不再写入某款游戏的操作时间。

同时设置定期保存，而不是每一帧都写磁盘。内存持续累加，达到保存间隔或发生关键状态变化时再持久化，避免为了统计毫秒数制造大量文件写入。

---

## 记录 264｜两个标签页共用一套左右切换和滚动状态

档案页面顶部放置 `ACHIEVEMENTS` 与 `STATISTICS` 两个标签，左右方向键或 `A/D` 可以切换，鼠标也能直接点击。

切换时必须把滚动位置归零。第一次没有重置，玩家在统计页滚到后半段，再切回成就页会直接落在成就列表中间，看起来像前面的内容消失了。

```python
profile_tab = selected_tab
profile_scroll = 0
```

`ESC` 和页面上的 `BACK` 都返回桌面。输入路径与设置中心一致，避免档案变成只能使用鼠标的特殊页面。

---

## 记录 265｜成就标签不复制成就墙，而是提供适合逐条阅读的另一种视图

成就墙适合看整套收藏，但徽章格子不适合连续阅读说明。玩家档案里的成就标签改成纵向列表，每一项有更完整的标题、说明和进度。

页面顶部先显示：

```text
COMPLETE 17 / 48   35%
```

未解锁项目显示 `current / target`，已经解锁的项目显示完成时间。一次只显示有限行，通过滚轮、`W/S` 或上下方向键移动。

这不是维护第二套成就数据，而是同一数据的另一种阅读方式：墙负责全貌，档案负责细节。

---

## 记录 266｜统计页按“区块”滚动，而不是把几十个数字挤在一张表里

统计内容比我预想的长。全局加七款游戏，再加扫雷不同棋盘的最佳时间，一屏不可能同时放下。

我把每一款游戏做成独立区块：标题行显示游戏名和该游戏的游玩时间，下方横向排列三到四项关键数字。页面一次显示四个区块，滚动时按区块移动。

这样比一张超长表更容易定位，也能让扫雷的模式时间拥有独立区块，不必用很小的字体塞到胜负数据旁边。

---

## 记录 267｜滚动值第一次没有封顶，列表末尾出现了整片空白

键盘向下时我最初只做了：

```python
profile_scroll += 1
```

如果玩家一直按住，数值会超过实际条目数，切片返回空列表，页面只剩标题和边框。虽然不会报错，但看起来像数据突然被清空。

我在每次绘制前根据当前标签、总条目数和可见行数计算最大滚动值：

```python
max_scroll = max(0, total - visible)
profile_scroll = min(profile_scroll, max_scroll)
```

向上则始终限制在零。鼠标滚轮和键盘最后都经过同一组边界，不再各自维护规则。

## 记录 268｜中文模式一屏少显示一条，换取说明真正可读

成就英文说明可以在较矮的行内显示，中文字体需要更多上下空间。如果强行保持六行，部分字会贴到边框，进度与说明也容易重叠。

我让中文成就列表每屏显示五条，并提高单行高度；英文继续显示六条。统计标签和数值在绘制前统一翻译，不再把 `MATCHES`、`BEST` 一类内部标签直接输出。

这次取舍减少了中文一屏的信息量，但滚动操作已经存在，可读性比勉强保持相同行数更重要。

---

## 记录 269｜档案让我发现有些统计只在结束时写入，会丢失中途取得的进度

把所有数字放到可见页面后，一些原来藏得很深的问题变得明显。

例如俄罗斯方块已经达到新等级，但如果程序异常退出，最高等级可能还没有写入；空袭行动在一局中已经取得更高分，也不应该只能等完整流程结束才保存。

我把适合即时更新的最高值放到成绩发生的时刻记录，结算时再做一次保险。完成局数仍然只在真正结算后增加，不能因为即时保存而提前算作通关。

玩家档案不仅展示数据，也反过来成为检查统计生命周期的工具。

---

## 记录 270｜为了鼓励通关，档案必须同时显示“开始过”和“真正完成”

如果页面只展示最高分，玩家很容易在某款游戏试一次后离开，而且看不出自己是否完整经历过它。

我保留了开始局数、完成局数、胜利、关卡进度和模式记录之间的区别。玩家打开档案时可以清楚看到：哪些游戏只是进入过，哪些已经完成过一局，哪些还有更高难度或特殊条件没有达到。

这种鼓励不依赖额外奖励，也不强迫玩家按固定顺序游玩。它只是把已经发生的过程诚实摆出来，让未完成部分自然显眼。

---

## 记录 271｜玩家档案完成后，掌机第一次能讲出一段属于玩家自己的历史

最后测试包括：

```text
新存档打开档案，所有计数为零且页面不报错
完成一局后，全局与对应游戏数据同时变化
中途退出只增加开始数，不增加完成数
两个标签切换时滚动归零
滚动到首尾不会越界
切换语言后标题、字段和说明仍在边框内
重启程序后，时间、记录与成就完成度保持一致
```

成就墙保存的是一组被点亮的目标，玩家档案保存的是这些目标之间的过程。做到这里，我已经不再把各游戏看成桌面上的七个独立按钮：开机、桌面、存档、设置、成就和档案开始共同记录同一个玩家在整台设备中的使用轨迹。

但内容层面仍有明显割裂。七款游戏除了统一外壳以外，各自没有任何关系。我开始思考，这台设备为什么能够同时容纳这些完全不同的世界。
