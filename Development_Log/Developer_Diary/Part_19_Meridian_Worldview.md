# 第十九部分：我不再把七款游戏解释成七个程序，而是给整台设备建立了存在的理由

---

## 记录 272｜系统越来越完整以后，最大的割裂反而来自内容本身

开机、密码、桌面、转场、音乐、设置、成就墙和玩家档案已经把外层体验连在了一起。但我连续从五子棋切到贪吃蛇，再进入空袭行动时，仍然觉得它们只是被同一个桌面装进来的七个程序。

每款游戏内部都能成立，放在一起却没有关系。桌面像文件夹，开机像包装，玩家无法回答一个最基本的问题：为什么偏偏是这七款游戏出现在同一台设备里？

我不想继续用更多按钮掩盖这个问题，决定进行一次比增加功能更大的调整——给整台设备建立统一世界观。

---

## 记录 273｜第一版设想是写一条贯穿七款游戏的主线，但很快发现会压扁玩法差异

我最初想让玩家按固定顺序完成七款游戏，把它们写成同一段冒险的七关。这个方案叙事容易理解，却会强迫五子棋、扫雷和空袭行动服从同一种逻辑。

五子棋需要抽象、安静的对弈感，空袭行动已经有明确的战争叙事，2048 又更适合数字生命的概念。把它们硬写成同一地点的连续关卡，只会让每款游戏原有的气质变弱。

我改成“一个器物、七个世界”的结构：外层设备负责连接，游戏保留各自完整的世界规则。

---

## 记录 274｜屏幕被重新定义为“共鸣透镜”，游戏模块则是稳定入口

统一设定的核心不是说设备里安装了七个软件，而是说它连接了七块彼此独立的现实。

```text
设备本体
  一件来历不明的跨维度器物

屏幕
  不是普通显示屏，而是观察异界的“共鸣透镜”

游戏模块
  不是模拟程序，而是通往不同世界的稳定入口

玩家
  被器物允许建立连接的持器者
```

这样开机校准、密码验证、桌面入口和七款玩法第一次能够被同一套语言解释，同时又不要求七个世界共享相同物理规则。

---

## 记录 275｜`HAO'S GAME DECK` 已经不能准确表达项目，我把它正式命名为 `MERIDIAN`

原名称强调的是“我的游戏掌机”，适合项目刚从小游戏合集升级为平台时使用。建立跨世界结构后，它已经无法表达设备在故事中的作用。

我选择 `MERIDIAN`，中文使用“子午线”。它既像一条贯穿不同区域的定位线，也能表达七个世界通过同一核心被校准、对齐和连接。

这次更名不是只修改标题图片。它代表项目定位再次变化：

```text
HAO'S GAME DECK
  一台承载多款小游戏的个人掌机

MERIDIAN
  一件连接多个异界、让游戏与系统共同参与叙事的器物
```

---

## 记录 276｜七款游戏各自得到一个世界名，而不是只加一段通用背景

我先为每款玩法确定世界名称和一句核心设定：

| 游戏 | 世界 | 核心设定 |
|---|---|---|
| 五子棋 | 阴阳棋境 / YIN-YANG BOARD | 混沌与秩序以黑白棋局推演宇宙命运 |
| 贪吃蛇 | 噬码渊 / CODE ABYSS | 灵蛇吞噬数据碎片，每一次进食都改写世界 |
| 打砖块 | 星穹壁垒 / STAR FORTRESS | 被囚禁的恒星碎片撞开失落文明的能量壁垒 |
| 2048 | 数灵海 / NUMEN SEA | 数字生命通过融合逐步觉醒 |
| 扫雷 | 雷原遗迹 / MINEFIELD RUINS | 大战百年后的排雷者清理土地并寻找旧世界痕迹 |
| 俄罗斯方块 | 筑天塔 / TOWER OF HEAVEN | 异星方块不断降临，建造者试图触及天空的答案 |
| 空袭行动 | 守望者战线 / WARDEN FRONT | WARDEN 对抗失控战争网络的最后战线 |

这些名称先从现有机制出发，再扩展意义，避免故事与实际游玩完全分离。

---

## 记录 277｜我要求每个世界都能解释玩家反复执行的核心动作

世界观如果只存在于菜单长文中，进入游戏后就会消失。因此我给自己定了一条规则：设定必须能够解释玩法中最常发生的动作。

```text
落子      → 两种宇宙力量继续推演
吞食      → 灵蛇吸收代码并增长
撞砖      → 恒星碎片释放被封存的记忆
合并      → 数字生命融合成更高意识
翻格插旗  → 排雷者恢复焦土
消行      → 筑塔者稳定不断坠落的结构
战斗      → WARDEN 推进对战争网络的反击
```

这让玩法没有因为叙事而改变规则，却获得了新的解释层。

---

## 记录 278｜五子棋的世界从“黑白对战”扩成混沌与秩序的长期棋局

五子棋最适合成为一个抽象世界。黑白双方不再只是界面颜色，而是两位没有姓名的古老存在：一方代表混沌，一方代表秩序。

它们用棋盘决定不同纪元的走向，每一颗棋子都可能对应另一个现实中的诞生或消逝。玩家不是旁观一盘普通棋，而是在接续一场早于时间开始的对弈。

我没有修改五连规则。世界观只强化了原有的黑白、网格、落子和胜利连线，让之前做过的磁吸、落子反馈和五连动画拥有更统一的语义。

---

## 记录 279｜贪吃蛇被解释成一条生活在底层代码中的灵蛇

贪吃蛇不断吞食、不断增长，最终因为撞到自己或边界而结束。这个循环很适合“衔尾”和“重启世界”的概念。

我把地图解释成现实表层之下的数据深渊，食物是漂浮的代码碎片，蛇没有名字，只有饥饿。每次开始新局，就像一次新的世界循环；蛇越长，维持它的空间越危险。

这样最高分、累计食物和长身体不再只是抽象数字，同时仍然保持原本快速、直接的街机节奏。

---

## 记录 280｜打砖块的“破坏”被改写为读取一座失落文明的图书馆

打砖块表面上是不断摧毁墙体。如果直接写成战争世界，它会和空袭行动过于接近。

我把砖墙设定为失落太空文明留下的能量档案，球是一块被囚禁的恒星碎片，挡板负责让它持续撞击并释放记录。

玩家看起来在拆墙，实际是在逐层打开一座壁垒图书馆。普通砖、坚固砖和关卡推进也因此可以理解为不同强度的封存结构，而不是无意义地增加耐久度。

---

## 记录 281｜2048 的合并不再只是加法，而是数字生命的融合与觉醒

2048 的核心动作是把相同数字合成更高数字。世界观如果只说“这是数字世界”，没有解释合并的代价，仍然太薄。

我将每个方块视为数灵。两个相同生命放弃各自独立形态，融合成一个携带双方过去的新意识。数值越高，意识越完整，2048 不再只是胜利数字，而是一次明显的觉醒节点。

达到 2048 后还能继续向 4096 推进，也可以解释为觉醒并没有停止。原来的继续游戏设计因此和世界概念自然衔接。

---

## 记录 282｜扫雷不能把地雷当成轻松装饰，我把重点放在战争之后的恢复

扫雷里的点击失败会直接触雷。如果把它写成寻宝或训练，会削弱旗帜、危险数字和谨慎推理的重量。

我设定战争已经结束一百年，但土地仍然无法使用。玩家扮演清理雷原的工程人员，每翻开一格都在恢复一小块安全区域，每插下一面旗都代表对后来者的警告。

不同棋盘密度对应不同危险区域，胜利不是击败敌人，而是让一片土地终于能够重新被穿过。

---

## 记录 283｜俄罗斯方块被设计成一座不断接收异星结构的通天塔

俄罗斯方块的方块永远从上方落下，玩家只能移动、旋转和排列。与其把它解释成普通建筑，我更喜欢“天空持续发送信息”的感觉。

七种方块成为某种异星建筑矩阵，地面上的建造者一边利用它们筑塔，一边尝试理解发送者。消行既是清理，也是让塔保持稳定；速度提高则像传输越来越急促。

玩家最终失败不是因为完成了塔，而是结构堆到无法继续接收。这个设定保留了原玩法中不断承压的感觉。

---

## 记录 284｜空袭行动已有自己的故事，我没有为了统一而重新推翻它

空袭行动已经拥有 WARDEN、关卡、Boss、武器路线和章节故事。给七界建立框架时，最危险的做法是把现有叙事全部重写成同一种神话口吻。

我保留守望者战线的战争网络设定，只补上它与器物的连接关系：MERIDIAN 捕捉到这个世界的紧急信号，玩家通过共鸣透镜参与 WARDEN 的战斗。

统一框架负责回答“为什么能进入”，空袭行动自己的故事继续回答“进入后发生什么”。

---

## 记录 285｜世界名放在菜单上还不够，我给每款游戏加入首次进入序章

如果玩家必须去外部文档才能知道世界观，游戏内部仍然是断裂的。

我给每个世界准备 3 到 5 行双语序章。第一次进入对应游戏菜单时，先显示全屏深色面板、世界标题和短文本；`Enter`、空格、点击或 `ESC` 可以继续。

序章只负责建立最小语境，不把玩家挡在长篇阅读前。进入五子棋前知道这是古老棋局，进入扫雷前知道自己在恢复焦土，已经足够让接下来的机制获得不同含义。

---

## 记录 286｜序章只自动出现一次，已读状态必须跨启动保存

第一次实现只用内存布尔值记录是否看过。关闭程序再启动以后，七款游戏的序章会全部重新弹出，重复游玩很快变得烦躁。

我在存档中增加：

```python
lore = {
    "prologues_seen": [],
}
```

序章关闭时把稳定的 `game_id` 写入列表并立即保存。以后进入菜单先检查该 ID，已经看过就直接显示正常菜单。

语言不是已读身份的一部分。玩家看过中文版后切到英文，不会被强制再看一次，但后续页面会按当前语言绘制。

---

## 记录 287｜菜单增加一句风味文字，让世界观在序章结束后仍然存在

只显示一次的序章仍然会被快速跳过。为了让世界身份长期留在游戏里，我在每款菜单标题与按钮之间加入一句短风味文字。

它不讲完整背景，只保持语气。例如噬码渊强调饥饿，数灵海强调融合与觉醒，雷原遗迹强调每一格安全区域都承载故事。

文字过长会挤压按钮，所以我限制它只承担一句话，并为英文与中文分别准备内容，不依赖逐字机器替换。

---

## 记录 288｜开机、密码和桌面也要服从新设定，不能只把游戏标题换掉

世界观不是七个菜单各自多一段文字。外层系统同样需要表现出它正在连接异界。

我把开机过程解释为共鸣校准、维度扫描、锚点稳定与核心连接；系统就绪不再只是普通操作系统完成加载，而是确认各界连接稳定。

密码页标题改为 `NEXUS AUTHENTICATION`，错误提示改为 `RESONANCE MISMATCH`。桌面状态栏使用 `MERIDIAN`，游戏图标下增加短副标题，让每个入口既保留玩法名称，又像设备中的一条连接通道。

这些改动没有改变原有输入和状态流程，只改变整套系统对自身的解释。

---

## 记录 289｜正式更名暴露出项目名已经散落在入口、包名、构建脚本和窗口标题里

我最初以为更名主要是修改界面文字，真正开始后才发现旧名称同时存在于多处：

```text
HAOS_GAME_DECK.py       → MERIDIAN.py
haos_game_deck/         → meridian/
窗口标题                → MERIDIAN
构建脚本与打包入口       → 新入口名
README 与项目结构        → 新名称与新包路径
模块导入                → meridian.*
```

只改一半会出现很隐蔽的问题：源码运行正常，但构建脚本还找旧入口；README 告诉用户执行不存在的文件；部分测试继续导入旧包。

我按入口、包目录、内部导入、构建命令、文档和测试逐层检查，确保 `HAO'S GAME DECK` 不再作为当前产品身份残留在运行路径中。

---

## 记录 290｜七个世界不能继续硬编码在七个页面里，我建立统一注册结构

每款游戏都需要世界名、概述、序章、菜单文字和桌面副标题。如果把这些字段分别散落在 `gomoku.py`、`snake.py` 和桌面代码中，任何格式调整都要修改七处。

我建立统一世界注册入口：

```python
register_game_world(
    game_id,
    world_name_en=...,
    world_name_zh=...,
    world_summary_en=...,
    world_summary_zh=...,
    prologue_en=[...],
    prologue_zh=[...],
    menu_flavor_en=...,
    menu_flavor_zh=...,
    desktop_subtitle_en=...,
    desktop_subtitle_zh=...,
)
```

菜单、序章和桌面通过 `game_id` 读取同一份定义，避免世界名在不同页面拼写不一致。

---

## 记录 291｜所有世界文本同时准备中英文，不让世界观成为汉化系统的例外

设置中心已经支持运行时切换语言，因此新加入的世界名、序章、风味文字、开机提示和认证提示也必须进入同一套语言流程。

世界注册结构保留英文与中文两份原始文本，不在运行时临时翻译长段故事。切换语言以后，下一帧从当前语言字段读取，已读状态和游戏进度保持不变。

我逐个打开七款游戏检查标题宽度、序章行距和桌面副标题，尤其处理中文像素字体在三倍缩放下容易超过面板的问题。世界观内容写完不代表页面已经能读，实际绘制仍然需要单独验收。

---

## 记录 292｜正式成为 MERIDIAN 后，故事有了结构，却还没有一个能集中阅读的地方

这次更新完成后，项目终于能够从内部解释自己的组成：一件名为 MERIDIAN 的器物，通过共鸣透镜连接阴阳棋境、噬码渊、星穹壁垒、数灵海、雷原遗迹、筑天塔和守望者战线。

玩家第一次进入游戏会看到序章，回到菜单仍有风味文字，开机、密码和桌面也使用相同概念。七款游戏不再只是同一文件夹里的内容。

但测试完整流程时，我发现故事被散在不同入口：器物背景在开机语言中，世界概述在首次序章里，更深设定没有稳定页面。看过一次序章后，玩家无法主动重新阅读。

世界观已经建立，下一步不是继续写更多零散文本，而是先解决这些内容应该放在哪里。
