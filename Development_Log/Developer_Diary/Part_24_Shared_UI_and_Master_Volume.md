# 第二十四部分：视觉回归守住画面以后，我开始统一像素界面和整机音量

---

## 记录 387｜对照二十四张基线时，我看到很多页面在重复解决同一个问题

视觉回归建立以后，我第一次能把桌面、设置、玩家档案、成就墙、世界档案和坦克页面放在同一套标准下比较。

它们的风格已经接近，但实现方式仍然分散：有的标题直接按二倍像素绘制，有的先测宽再降倍率；有的面板画三层矩形，有的只画外框；英文 HUD 从左开始排，中文 HUD 还在依赖固定坐标。

继续逐页修补会产生一个循环：这一页解决了长文字，下一页又复制一套稍有不同的缩放；某个边框改成四像素，另一个页面仍保留五像素。

我决定只抽出最重复、最容易造成视觉回归的基础动作，不重写整套页面系统。

---

## 记录 388｜公共像素 UI 首先只做三个原语

我新增 `ui_components.py`，首批只放三件事：

```text
fit_pixel_text
  在安全宽度内选择最大的整数像素倍率

draw_pixel_panel
  用统一的外框、内层和整数边距绘制面板

anchored_blit
  按 center / midleft / midright 稳定放置图像
```

我没有立刻做一个包含按钮、列表、分页、弹窗和主题的庞大框架。现有页面已经能运行，先统一最底层的文字、面板与锚点，就能解决大量重复问题，同时避免把每个游戏的配色和布局个性抹掉。

---

## 记录 389｜文字适配必须保持整数像素倍率

普通 UI 可以把文字任意缩放到 1.73 倍，像素字体不行。非整数缩放会产生模糊边缘，让同一页面的字看起来像来自两套字体。

`fit_pixel_text()` 从偏好的整数倍率向下尝试：

```python
for scale in range(preferred_scale, 0, -1):
    rendered = render_pixel_text(font, text, color, scale=scale)
    if rendered.get_width() <= max_width:
        return rendered
```

如果一倍仍然超宽，才裁切到安全宽度。裁切不是理想结果，但比把文字推到面板外或使用模糊的小数缩放更可控。

这也让中英文遵守同一规则：先尽量保持设计字号，再按实际宽度降到下一个整数倍率。

---

## 记录 390｜面板边框第一次被写成小数，测试直接拒绝

像素面板的内缩边距如果是 `2.5`，Pygame 最终会发生取整，左右两侧可能不再一致。肉眼看起来只是一条边稍厚，连续页面放在一起却会显得不稳定。

我让 `draw_pixel_panel()` 只接受非负整数：

```python
if isinstance(border, bool) or not isinstance(border, int):
    raise TypeError("border must be an integer pixel count")
```

先画外层轮廓，再按两倍边距缩小得到内部矩形。内部尺寸已经小于零时不继续绘制，避免极小面板抛出异常。

这里宁可让错误参数尽早失败，也不让渲染层默默替我决定怎样取整。

---

## 记录 391｜右侧信息不再通过“估算文字宽度”摆放

坦克蓝方 HUD、设置数值和一些返回提示都需要贴着右侧排列。以前常见写法是先渲染，再手动计算 `screen_width - text_width - margin`。每个页面的 margin 不同，翻译后又容易漏改。

我把位置描述成锚点：

```python
anchored_blit(surface, image, target_rect, "midright")
```

函数先根据目标矩形取得 `midright`，再把图像的同名锚点对齐过去。居中和左侧同理。

页面只表达“这段信息属于右侧区域”，不再重复计算文字从哪里开始。中文变宽时向左延伸，右边界仍然保持不动。

---

## 记录 392｜我没有一次替换全部旧函数，而是保留入口逐步委托

直接删除各页面原来的面板和文字函数，改动范围会同时覆盖所有游戏。一处参数语义不一致，就可能让整个项目无法启动。

我保留旧函数签名，让它们内部逐步转调新的公共原语。页面原有调用暂时不用改变，颜色仍从各自调色板传入。

迁移顺序先从设置中心、玩家档案、成就墙、世界档案和坦克页面开始，因为它们已经有双语视觉基线和密集布局。其他游戏可以在后续修改时继续接入，不需要为了形式统一一次性重写。

公共层的目标是减少重复判断，不是让所有页面长成同一张面板。

---

## 记录 393｜“画得出来”之外，我开始为重要区域写不重叠约束

视觉图片能发现回归，但一张图只代表一个语言和一个状态。我为容易发生碰撞的区域暴露布局矩形：

```text
设置按钮
玩家档案标签
成就徽章与分页控制
档案分类与条目列表
坦克菜单、暂停、结算内容
```

测试要求所有受保护矩形都在 1280×720 画面内，同一组中的矩形不能互相相交。档案分类数量也必须与生成出的标签矩形数量相同。

这些测试不判断颜色是否漂亮，但能在绘制前就发现“新标签把返回按钮挤住”这类结构问题。

---

## 记录 394｜声音已经分为音乐和音效，但还缺少真正的整机总音量

音频系统早已可以单独调节 BGM 与 SFX，也有静音开关。实际使用时却有一个很明显的问题：我想让整台设备整体小一点，必须分别移动两个滑块；之后想恢复原来的音乐与音效比例，又要记住两个旧值。

这不像一个掌机的总音量，更像两个互不相关的开发参数。

我增加 `master_volume`，让它只控制最终输出，不破坏音乐和音效之间已经设置好的相对关系。

---

## 记录 395｜旧存档没有主音量字段，默认值必须通过深合并补进去

新的设置结构加入：

```python
"master_volume": 1.0
```

不能因为旧存档缺少这一项就把整个 settings 重置，否则玩家已经选择的语言、音乐、音效和动画等级都会丢失。

存档加载继续使用深合并：旧数据已有的字段保留，新增的主音量只在缺失时补默认值。读取后再把数值限制在 `0.0` 到 `1.0`。

这样更新后的第一次启动听起来与更新前一致，玩家再自行调整总量。

---

## 记录 396｜音乐、音效和场景淡化终于经过同一条混音公式

我把最终音量明确写成两条公式：

```text
music output
  = master × music × scene scale

sfx output
  = master × sfx × event gain
```

`scene scale` 用于转场或特定状态淡化音乐，`event gain` 是单个音效自己的强弱，例如按键比爆炸轻。它们都不能绕过主音量。

对应实现集中为：

```python
effective_music_volume()
effective_sfx_volume(event_gain)
```

交叉淡化中的新旧音乐通道也每帧使用最终音乐音量，不再只在开始播放时设置一次。

---

## 记录 397｜静音保持独立，不再通过把三个滑块都改成零实现

静音表达的是“暂时不输出”，不是“忘记我的音量设置”。

所以 `muted` 为真时，两条有效音量函数直接返回零；取消静音后，主音量、音乐音量和音效音量仍保持原值。

如果用把滑块写成零的方式实现静音，取消时就必须额外保存三个旧值，还会与拖动滑块、存档恢复和设置重置互相影响。独立布尔状态让语义更清楚。

---

## 记录 398｜坦克炮弹暴露了绕过主音量的旧调用

公共公式完成后，我逐条检查音效入口。坦克对决的射击、碰撞和道具拥有各自事件增益，最容易出现“音乐变小了，炮声仍然很响”的情况。

所有 `Sound` 播放都改为先计算有效音量。例如主音量 `0.5`、音效音量 `0.8`、某个事件增益 `0.46` 时，最终输出应为：

```text
0.5 × 0.8 × 0.46 = 0.184
```

测试直接验证这个结果，并检查静音时无论事件增益多大都返回零。

这一步的重点不是某个具体数值，而是任何游戏都不能绕过整机控制直接写通道音量。

---

## 记录 399｜桌面角落的扬声器不再只做一个简单开关

整机音量加入后，桌面需要一个比“点一下静音”更完整的入口。我不想让玩家每次都进入设置中心，也不想在桌面长期摆放三条占空间的滑块。

最后保留一个小扬声器标签。点击后从标签右侧展开音量面板，包含：

```text
MASTER
MUSIC
SFX
```

它是快速控制，不替代设置中心。面板关闭时只占原来的小图标位置，不挤压桌面应用。

---

## 记录 400｜三条滑块共享结构，但数值和写入入口各自独立

每一行都包含翻译后的标签、当前值、setter 和可点击轨道：

```python
("master", "MASTER", audio.master_volume, audio.set_master_volume)
("music", "MUSIC", audio.music_volume, audio.set_music_volume)
("sfx", "SFX", audio.sfx_volume, audio.set_sfx_volume)
```

鼠标位置相对轨道左端换算成 `0.0` 到 `1.0`，setter 再负责限制范围。

我没有让桌面直接修改音频对象的内部字段。这样主音量更新时可以立即刷新交叉淡化，音乐和音效也继续遵守自己的状态同步逻辑。

---

## 记录 401｜第一次让面板瞬间出现，功能正确但很像调试工具

最初点击扬声器后，330×150 面板立刻完整出现。三条滑块都能拖动，保存也正常，但体验上像突然盖出一块开发面板，与桌面已有的像素动画和设备感不一致。

我决定让它从标签旁向右展开，并加入很轻的回弹。这里的动画不是为了炫技，而是让玩家看清“这个面板来自哪个入口”，关闭时也知道它收回到了哪里。

但回弹不能改变滑块数值，也不能让面板越过屏幕边界。表现状态必须和音量状态分开。

---

## 记录 402｜动画被拆成纯状态机，只消费传入的 `dt_ms`

我新建独立 `VolumePanelState`：

```text
closed
opening
open
closing_content
closing_width
```

更新函数只接收当前状态、经过时间和动画等级，返回宽度比例、内容透明度、三行偏移与可交互区域。

它不读取 `pygame.time.get_ticks()`，也不直接绘制。这样给定相同 `dt_ms` 序列就一定得到相同几何结果，动画可以在没有窗口的测试中逐帧验证。

---

## 记录 403｜完整、减少和关闭动画不能只靠“播放速度乘一个系数”

设置中心已有三档动画等级。我为音量面板分别定义体验：

```text
full
  展开约 420ms，回弹较明显，最大宽度比例 1.08

reduced
  展开约 240ms，回弹更轻，最大宽度比例 1.04

off
  立即进入完全打开或关闭状态
```

减少动画不是简单把完整动画快放。它同时降低持续时间和过冲强度，避免对动画敏感的玩家仍然看到明显弹跳。

关闭动画时状态机也要正确清理拖动目标，不能因为跳过过渡停留在不可见的交互状态。

---

## 记录 404｜回弹第一次只看曲线，没有限制宽度，面板可能顶出安全区域

展开使用 ease-out-back 曲线。这个曲线会自然超过 `1.0` 再回落，如果不限制，参数稍有调整就可能让面板右边越过预留区域。

我为每档动画加入明确的 `overshoot_limit`，并在计算后同时限制下界与上界：

```python
width = min(limit, max(0.0, ease_out_back(progress)))
```

布局测试使用过冲后的最大矩形检查屏幕边界，而不是只测试最终静止位置。动画中间帧同样属于真实界面。

---

## 记录 405｜关闭时先淡掉内容，再收回外壳

第一次把宽度和内容一起缩小时，三行文字与滑块会在越来越窄的面板里被挤压、裁切，看起来像布局坏了。

我把关闭拆成两段：

```text
closing_content
  面板保持完整宽度，文字和滑块先淡出

closing_width
  内容已经不可见，外壳再向扬声器标签收回
```

三行在收回阶段还带少量错开位移，但不再承担可读信息。这样关闭过程更像设备抽屉合上，而不是一张页面被横向压扁。

---

## 记录 406｜面板还在展开时，玩家不能点击尚未到位的滑块

动画初期，视觉上的轨道仍然很短。如果直接按最终矩形响应鼠标，玩家会点击一个画面上还不存在的位置，却突然改变音量。

我让几何结果只有在完全 `open` 时才提供 `interactive_rect`。展开、淡出和收回阶段都不接受滑块与关闭按钮点击。

开始拖动后，鼠标移动持续更新同一目标；松开时写入最终值并保存。切换桌面页、关闭面板或离开桌面会取消拖动，避免隐藏面板继续响应鼠标。

画面显示到哪里，交互范围就只能到哪里。

---

## 记录 407｜这一轮把“统一”限制在可验证的公共规则上

完成后，设置中心、玩家档案、成就墙、世界档案和坦克页面开始共享文字适配、像素面板和锚点；关键布局拥有边界与不重叠测试。音频输出则统一经过主音量，桌面提供三滑块弹出面板。

我没有把所有页面重写成一个模板，也没有让每款游戏放弃自己的颜色和构图。真正统一的是：

```text
像素字号只能按整数变化
长文字必须服从安全宽度
左右信息使用稳定锚点
面板边距不能靠隐式取整
所有声音都经过同一混音链
动画几何与交互区域保持一致
```

视觉回归负责守住结果，布局和状态测试负责守住规则。这个公共层终于不只是“看起来差不多”，而是有一组能被反复验证的约束。
