# 第五部分：让平台开始处理连续碰撞——打砖块

---

## 记录 45｜贪吃蛇之后，我想做一种不依赖网格移动的玩法

贪吃蛇接入桌面以后，掌机已经能处理持续更新和键盘方向输入。但蛇的所有位置仍然是整数网格，移动也只是每隔几帧跳到下一格。

下一款游戏我决定做打砖块。

它同样是即时玩法，但球的位置和速度需要连续变化，还要处理墙面、挡板和砖块三种碰撞。玩家不是直接控制球，而是通过挡板间接改变反弹方向。

这次开发的重点因此不只是“再增加一个游戏”，而是确认现有游戏区域能不能容纳浮点运动、连续按键和碰撞反馈。

我仍然先把范围限制在最基本的循环：

```text
移动挡板
   ↓
球在场地内反弹
   ↓
击碎砖块并得分
   ↓
球掉出底部时损失生命
   ↓
生命耗尽后结束
```

## 记录 46｜先把球、挡板和砖块写成三种独立状态

打砖块不能像贪吃蛇一样只用一组坐标列表表示全部规则。我分别保存球、挡板和砖块：

```python
ball = {
    "x": board_center_x,
    "y": board_bottom - 70,
    "vx": initial_vx,
    "vy": initial_vy,
    "radius": 8,
}

paddle = {
    "x": board_center_x - paddle_width / 2,
    "y": board_bottom - 36,
    "width": paddle_width,
    "height": 16,
}
```

砖块先排成 5 行 8 列，共 40 块。每块保存自己的矩形、行列和 `alive` 状态。砖块之间留 6 像素间隔，高度为 26 像素；宽度则根据 504 像素游戏区域自动计算。

```python
rows = 5
columns = 8
gap = 6
brick_width = (504 - gap * (columns + 1)) // columns
```

第一版暂时不加入复杂砖块类型。每块砖被击中一次就消失并增加 10 分，先确保球能够稳定地打完整个布局。

## 记录 47｜球撞到墙以后，不能只把速度乘以 -1

球每帧按照速度更新位置：

```python
ball["x"] += ball["vx"]
ball["y"] += ball["vy"]
```

最初检测到球越过左右边界时，我只反转了横向速度。测试中偶尔会看到球在墙边快速抖动：这一帧球已经进入墙外，速度虽然反向，下一帧仍可能没有完全回到边界内，于是再次触发反转。

最后在反转速度前，先把球的位置夹回合法区域：

```python
if ball_x - radius <= board_left:
    ball_x = board_left + radius
    ball_vx = abs(ball_vx)

elif ball_x + radius >= board_right:
    ball_x = board_right - radius
    ball_vx = -abs(ball_vx)
```

顶部边界使用同样的处理。底部则不反弹，因为越过底部代表这次接球失败。

这次问题让我区分了“发现碰撞”和“解决穿透”：只改变方向并不会自动把已经进入障碍物的物体移出来。位置修正和速度修正必须一起完成。

## 记录 48｜用球心判断碰撞，会漏掉擦边的球

第一版砖块碰撞只判断球心是否进入砖块矩形。正面击中通常没有问题，但球从砖块边缘擦过时，画面上已经明显接触，规则却认为没有碰撞。

原因是球有 8 像素半径，不能被当成一个点。

我改成圆形与矩形的碰撞判断：先找到矩形中距离球心最近的点，再计算这个点到球心的距离是否小于半径。

```python
closest_x = max(rect.left, min(ball_x, rect.right))
closest_y = max(rect.top, min(ball_y, rect.bottom))

hit = (
    (ball_x - closest_x) ** 2
    + (ball_y - closest_y) ** 2
    <= radius ** 2
)
```

挡板和砖块都复用这一个判断，不再各自写一套近似命中范围。这样球的外缘接触到矩形时，画面与规则会在同一时刻确认碰撞。

## 记录 49｜挡板不能只负责把球原路弹回去

最简单的挡板反弹是把 `vy` 变成负数。试玩后很快发现，这样玩家对球的方向几乎没有控制力。如果球一直以接近垂直的角度运动，挡板左右移动只是在追球，无法主动改变下一轮轨迹。

我开始根据球击中挡板的位置计算反弹角度。

先把碰撞点换算成 `-1.0` 到 `1.0`：击中挡板中心为 0，最左侧接近 -1，最右侧接近 1。再把这个比例映射到左右最大 65 度。

```python
impact = (ball_x - paddle_center_x) / (paddle_width / 2)
impact = max(-1.0, min(1.0, impact))

angle = impact * radians(65)
ball_vx = sin(angle) * speed
ball_vy = -cos(angle) * speed
```

击中中心时，球接近垂直向上；击中边缘时，横向分量更大。玩家因此可以通过移动挡板来瞄准剩余砖块。

碰撞成立后，还要把球放到挡板上沿以上一像素，并且只在球向下移动时检测挡板。否则球已经反弹向上，却仍与挡板矩形重叠，下一帧可能再次被计算一次反弹。

## 记录 50｜多次碰撞以后，球速会慢慢偏离设定值

加入不同角度的反弹后，我发现球经过多次碰撞，速度大小可能逐渐发生变化。特别是砖块边缘碰撞与挡板角度计算交替发生后，某一方向分量会变得很小，球可能长时间近乎水平地来回移动。

这种轨迹虽然没有违反数学规则，却会让一局游戏停滞：球一直在同一高度往返，很难接触上方或下方目标。

我增加了速度归一化。每次重要碰撞后，重新计算当前速度长度，再按目标速度同比例缩放横纵分量：

```python
current_speed = sqrt(vx * vx + vy * vy)
scale = target_speed / current_speed

vx *= scale
vy *= scale
```

同时规定纵向速度绝对值不能低于 2.4。如果 `vy` 太小，就先恢复到最低纵向速度，再根据总速度重新计算 `vx`。

这样球仍然会因为击中挡板不同位置而改变角度，但不会越打越快、越打越慢，也不会陷入几乎水平的无效轨迹。

## 记录 51｜砖块角落碰撞时，反转哪个方向不能靠猜

球击中砖块后需要判断应该反转横向速度还是纵向速度。

第一版无论从哪边撞到砖块都反转 `vy`。从上方或下方命中时看起来正常，但从侧面擦到砖块时，球会像穿过砖块边缘一样突然上下转向。

我改为比较球四个方向与砖块四条边的重叠距离：

```text
球右侧到砖块左边的重叠
砖块右边到球左侧的重叠
球下侧到砖块上边的重叠
砖块下边到球上侧的重叠
```

最小重叠位于左右两侧时反转 `vx`，位于上下两侧时反转 `vy`。

一帧内只处理第一块确认命中的砖块，然后立即结束砖块循环。否则球刚好压在两块相邻砖的边缘时，可能在同一帧同时消除两块并连续反转两次，最后方向反而没有变化。

被击中的砖块先把 `alive` 设为 `False`，再增加 10 分、产生碎片，并归一化球速。规则、得分和反馈都由同一次碰撞触发。

## 记录 52｜一条命不能让失误直接清空整局进度

第一版球掉出底部后直接结束，实际玩起来容错太低。打砖块需要先熟悉反弹角度，如果一次没接住就重来，玩家很难形成连续节奏。

我给每局设置 3 条生命。球掉出底部时减少一条生命；只要生命仍大于 0，就保留已经打掉的砖块和当前分数，把球重新放回挡板上方。

```text
球掉出底部
   ↓
生命 -1
   ↓
仍有生命：只重置球
没有生命：进入结束页
```

所有砖块被清除以后进入下一关。关卡数增加一，重新生成 5×8 砖块，并让目标球速在原难度基础上每关增加 0.35。

这种关卡处理暂时不更换砖块排列，重点是把一局从“清完一次布局”延长成可以继续挑战的过程。分数、剩余生命和关卡都在同一局中保留。

## 记录 53｜键盘和鼠标控制不能共享同一种更新方式

用 `A/D` 或左右方向键控制挡板时，每帧根据按键状态增减横坐标，适合需要稳定移动速度的键盘操作。

但鼠标如果也使用“鼠标在左边就向左移动”的方式，挡板会一直追着鼠标，反应显得拖沓。我把鼠标模式改成直接让挡板中心跟随鼠标横坐标：

```python
paddle_x = mouse_x - paddle_width / 2
```

两种模式最后都要把挡板限制在游戏区域内，不能让它的一部分移出边界。

开始页增加设置入口，控制方式可以选择 `KEYBOARD` 或 `MOUSE`。右侧操作提示也跟随当前控制模式变化，避免已经切到鼠标后仍然只显示 `A/D Move`。

这次让我意识到，支持两种输入不只是给同一个动作绑定更多按键。不同设备的移动语义不同，更新方式也应该随之变化。

## 记录 54｜难度不能只改球速

测试普通速度后，我加入了 `EASY`、`NORMAL` 和 `HARD` 三种难度。

如果难度只改变球速，困难模式会更快，但挡板仍然很宽，实际容错变化不够明显。于是把球速、挡板宽度和挡板移动速度作为一组参数：

```text
EASY    球速 4.5   挡板宽 158   键盘速度 8
NORMAL  球速 5.2   挡板宽 126   键盘速度 9
HARD    球速 6.3   挡板宽  96   键盘速度 10
```

切换难度时，如果挡板已经存在，就先记录它的中心位置，再修改宽度，最后用原中心重新计算左侧坐标。否则改变宽度会让挡板只向右伸缩，看起来像突然横移。

设置页还允许分别选择球、砖块和挡板颜色。颜色只影响表现，不改变碰撞和得分；难度参数则只影响规则，不与皮肤选择混在一起。

## 记录 55｜击中砖块以后，需要让玩家感到“真的打碎了”

规则完成时，砖块只是从列表中被标记为不可见。球碰上去，砖块下一帧消失，右侧分数增加 10。功能正确，但击碎过程几乎没有重量。

我给不同碰撞增加了不同强度的反馈：

- 撞墙时产生少量球色像素；
- 击中挡板时产生 8 个挡板色像素，并进行 5 帧轻震；
- 击碎砖块时产生 14 个砖块色像素；
- 得分数字进行 14 帧、最大 8 像素的跳动。

粒子向四周散开并受轻微重力影响，生命结束后从列表移除。它们不参与碰撞，也不会改变球速。

对局界面继续使用左、中、右三段布局：左侧竖排 `BRKOUT`，中间放 504 像素场地，右侧显示 `SCORE`、`LIVES`、`BEST` 和当前操作提示。

结束时保留最后的场地作为背景，加半透明遮罩，再让结果面板在 22 帧内使用回弹曲线放大。面板只提供重新开始和返回游戏菜单，退出到桌面仍然由开始页负责。

## 记录 56｜第二个预留栏被打砖块替换

游戏内部稳定以后，我才把打砖块接入掌机桌面。

新图标画出三行小砖块、底部挡板和中间小球。它与五子棋、贪吃蛇图标使用相同卡片尺寸，但内部图案直接表达自己的玩法。

桌面点击进入打砖块开始页，再由开始页进入设置或对局。退出游戏后，球、挡板和砖块都停止更新，不会在桌面背景中继续运行。

最后反复测试了这些路径：

- 球在左右和顶部边界不会卡墙或连续反转；
- 擦边碰撞能被圆形与矩形检测捕获；
- 击中挡板不同位置会得到不同反弹角度；
- 球速在多次碰撞后仍保持目标大小，纵向速度不会接近零；
- 一帧只消除一块砖，得分每块增加 10；
- 掉球只损失一条生命，三条生命耗尽才结束；
- 清空砖块后进入更快的新关卡；
- 键盘和鼠标模式都不会把挡板移出场地；
- 重新开始会清理旧粒子、震动、分数、生命和关卡；
- 返回桌面后再次进入，先回到打砖块自己的开始页。

完成这款游戏以后，掌机不仅能处理网格移动，也开始处理连续坐标、反弹角度和浮点碰撞。桌面上的第二个预留位置也变成了真正可玩的内容。
