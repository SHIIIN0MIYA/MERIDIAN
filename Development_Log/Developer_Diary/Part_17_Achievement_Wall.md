# 第十七部分：通知会消失，所以我给已经完成的目标做了一面真正能回看的墙

---

## 记录 242｜成就能够解锁以后，我第一次发现“出现过”不等于“留下来”

成就通知解决的是达成瞬间的反馈：顶部面板滑入，告诉玩家刚刚完成了什么，然后退出，不打断当前游戏。

但我连续试玩几局后发现，它只解决了几秒钟的问题。通知消失以后，玩家无法重新确认自己已经拿到哪些成就，也不知道其余目标还差多少。存档里虽然完整保存了 48 个稳定 ID 和解锁时间，画面上却没有一个长期入口。

这让我觉得成就系统仍然像后台统计工具，而不像掌机里真正存在的一项功能。

我决定不把列表临时塞进设置页，而是在桌面上增加一个独立的 `WALL` 图标，做一整面成就墙。

---

## 记录 243｜48 项成就刚好排成 8×6，我先坚持让玩家一眼看到全貌

第一版布局直接由现有 48 项成就决定：8 列、6 行，不滚动，也不分页。

```text
8 columns × 6 rows = 48 badges
```

如果改成普通纵向列表，玩家一次只能看到五六项，很难形成“我正在填满一整套收藏”的感觉。成就墙的重点不是阅读长文字，而是让锁定与解锁状态同时构成一张完整进度图。

我先计算可用面板的宽高，再统一推导徽章尺寸和间距。所有格子都来自同一个确定性布局函数，绘制、点击和测试共用同一组矩形，避免画面位置与命中区分别维护。

---

## 记录 244｜成就墙只读取现有数据，不再建立第二套“墙存档”

最容易留下技术债的方案，是给成就墙再保存一份解锁状态。这样成就系统和墙一旦有一边写入失败，就会出现通知已经弹出、墙上仍然锁着的矛盾。

我让墙直接读取原来的两类数据：

```python
ACHIEVEMENTS
save_data["achievements"]
```

前者提供标题、说明、所属游戏、统计键和目标值；后者只保存稳定 ID 与解锁时间。墙本身只维护当前按下的徽章、正在查看的徽章和动画帧，不增加任何永久字段，也不修改存档结构。

这样成就达成、顶部通知、成就墙展示始终以同一个结果为准。

---

## 记录 245｜我把成就墙做成独立页面，而不是盖在桌面上的大弹窗

成就墙需要同时容纳 48 枚徽章、完成数量、操作提示和详情动画。如果直接叠在桌面上，背景图标和时钟会继续吸引视线，输入也容易穿透到桌面。

因此我增加了独立状态：

```text
DESKTOP
  ↓ open_achievement_wall
ACHIEVEMENT_WALL
  ↓ ESC
DESKTOP
```

桌面按钮只负责进入，成就墙状态自己处理绘制、鼠标按下、鼠标释放和返回。这样它与设置中心、各游戏菜单一样，是掌机中的正式应用，而不是一次性浮层。

---

## 记录 246｜锁定徽章不能完全隐藏目标，否则玩家不知道该往哪里努力

我最初考虑过把所有未解锁徽章都显示为 `???`。实际看起来确实神秘，但 48 个暗格里如果有大半完全没有信息，玩家只会看到一堵无法理解的墙。

最后锁定状态保留标题或简化提示，并显示当前进度：

```text
locked:   dark panel + muted border + lock mark + current / target
unlocked: bright panel + gold border + cyan accent + completion mark
```

这样未完成项目仍然能告诉玩家目标方向，已经完成的项目则在整面墙上形成明显亮区。成就墙既是收藏展示，也是下一步游玩路线的提示。

---

## 记录 247｜徽章图案没有依赖外部图片，而是根据成就身份生成像素图标

48 个徽章如果全部手工准备图片，资源管理会突然变成新的负担，而且不同游戏很容易画成完全不同的风格。

我选择用成就 ID 和所属游戏生成小型点阵图案，在固定像素网格中绘制不同分布。图案不是随机到每次启动都变化，而是同一个 ID 始终得到相同结果。

解锁状态再叠加金色标记和主题色，锁定状态降低亮度。这样每枚徽章都有稳定辨识度，同时仍然保持整面墙统一的像素语言。

---

## 记录 248｜第一次只做悬停放大后，点击手感仍然像网页按钮

初版徽章在鼠标悬停时轻微放大并提高边框亮度，功能上已经能够指出当前目标，但按下鼠标时没有任何变化，释放后详情突然出现。

我补上了明确的按压状态：鼠标按下时记录徽章索引，只有在同一枚徽章内释放才打开详情；如果按下后把鼠标移出，动作取消。

```text
mouse down on badge A
  → remember A

mouse up on badge A
  → open A

mouse up elsewhere
  → cancel
```

这个处理避免了拖动经过其他徽章时误开详情，也让按钮有了完整的悬停、按下、释放三段反馈。

---

## 记录 249｜详情不能突然弹到中央，我让它从原来的徽章位置长出来

墙上的徽章空间很小，只适合显示标题和短进度；完整说明、解锁时间和目标需要单独详情页。

第一次实现直接在中央画一个大面板。信息是对的，但玩家点击左下角徽章后，视线突然被拉到中央，无法直观确认详情属于刚才哪一枚。

我改为保存被点击徽章的源矩形，在 24 帧内把位置和尺寸插值到中央详情矩形。背景同时逐渐变暗，文字等面板接近目标大小以后再淡入。

```python
current_rect = interpolate(source_rect, detail_rect, eased_t)
```

打开过程加入轻微回弹，使它更像一枚实体徽章被拿起放大，而不是新页面硬切换。

---

## 记录 250｜关闭动画第一次写反，按 ESC 时详情反而闪回最大尺寸

打开动画完成后，我复用了同一个进度值处理关闭，并在关闭状态把 `t` 再做一次反转。

结果测试时出现明显闪烁：按下 `ESC`，面板本该从中央缩回徽章，却先重新跳到最大尺寸，再开始变化。

问题是关闭过程已经通过逐帧减少 `detail_frame` 让 `t` 自然下降，又额外执行了一次反转，相当于把方向改了两遍。

我移除第二次反转，让同一个插值函数只根据当前帧得到位置。打开时帧数增加，关闭时帧数减少，方向由状态更新决定，不再由绘制函数猜测。

---

## 记录 251｜详情停留太久以后，关闭按钮看起来会失效

另一个 Bug 只在详情打开一段时间后出现。详情帧数在完全展开后仍持续增加，例如已经累积到一百多帧。点击关闭时，程序从这个数值开始逐帧减到 24，前面几十帧的插值都被封顶为 1，画面没有任何变化。

玩家看到的结果就是：已经点了关闭按钮，面板却停在原地，过一会儿才开始缩小。

我增加统一关闭入口，在开始关闭时先把帧数限制到动画长度：

```python
detail_frame = min(detail_frame, 24)
detail_closing = True
```

无论详情停留多久，点击关闭、点击面板外部或按 `ESC` 都会立刻出现反向动画。

---

## 记录 252｜ESC 必须按层级处理，不能一次把详情和整面墙一起关掉

成就墙里存在两层界面：墙本身和徽章详情。如果详情打开时按一次 `ESC` 就直接回到桌面，玩家很难继续查看相邻徽章。

最后的规则是：

```text
详情打开时按 ESC
  → 只关闭详情

没有详情时按 ESC
  → 返回桌面
```

鼠标点击详情外部也只关闭详情。这个层级与视觉结构一致，玩家不需要记住特殊操作。

我专门测试了打开、关闭、再次返回三段状态，防止关闭动画尚未结束时第二次输入造成索引提前清空。

---

## 记录 253｜详情里同时展示进度与解锁时间，锁定和已完成使用不同语义

同一个详情面板需要服务两种状态。

锁定时最重要的是：成就说明、当前值和目标值。已解锁时继续显示 `target / target` 意义不大，我改为展示真正写入存档的解锁时间。

```text
未解锁
  标题 / 说明 / 当前进度 / 目标

已解锁
  标题 / 说明 / 已完成状态 / 解锁时间
```

时间来自成就达成时已经保存的 `unlocked_at`，不是打开墙时临时生成。这样玩家看到的是实际完成时刻，不会因为重启或切换语言改变。

---

## 记录 254｜中文标题和长说明让我重新检查了徽章与详情的文字尺寸

英文成就标题大多可以用两倍像素倍率放进徽章，但中文字符更宽，详情说明也更容易换行。如果所有文本都固定同一倍率，部分徽章会挤到边框，详情提示会和关闭按钮争空间。

我给文字绘制增加逐级缩放：先尝试预期倍率，超过最大宽度再降一级；详情说明使用独立行距。底部完成数量与 `ESC` 提示放进单独状态条，不再和最后一排徽章共享空间。

这次调整没有改变成就内容，只解决同一信息在两种语言下都能保持像素边界清楚的问题。

---

## 记录 255｜我把成就墙当作一个可测试的交互系统，而不只检查截图是否好看

最后测试不只调用绘制函数，还验证实际状态变化：

```text
布局函数返回 48 个互不重叠的徽章矩形
点击某一格后，详情索引与该格一致
按 ESC 先关闭详情，再按一次才返回桌面
锁定项目显示当前进度
已解锁项目读取保存时间
关闭动画立即开始，不闪回、不等待
```

我也用零成就、部分解锁和全部解锁三种数据检查整面墙，确认颜色差异足够明显，完成数量与真实字典一致。

---

## 记录 256｜成就终于有了永久展示，但我还看不到“这个玩家整体玩成了什么样”

完成后，成就系统形成了完整闭环：游戏产生统计，条件满足后永久解锁，顶部通知给出即时反馈，桌面成就墙负责长期回看。

不过连续使用几天后，我又感到信息仍然被切成两半。墙很适合展示目标，却看不到总游玩时间、各游戏完成局数、最高分、胜负和不同模式记录。玩家可以知道自己亮了多少枚徽章，却无法从一个地方看到整台掌机留下的游玩轨迹。

这不是成就墙应该继续承担的内容。把更多数字硬塞进每枚徽章只会破坏它的收藏作用。我需要另做一个以玩家数据为中心的页面。
